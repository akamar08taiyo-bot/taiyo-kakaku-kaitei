# Handoff: 価格改定のご案内（営業所選択機能付き A4 文書）

太陽シルバーサービス株式会社 向け「紙製品価格改定に伴うお早めのご発注のお願い」A4 1ページ文書ジェネレーター。
19営業所の切り替え、担当者情報の手入力、対象商品1〜6件の追加／編集、案内文全文の編集、書体16種の切替、PDFダウンロードと印刷に対応。

## このバンドルの中身

| ファイル | 内容 |
|---|---|
| `index.html` | **デプロイ用の完成品。** 依存なしの単一HTML（バニラJS）。静的ホスティングにそのまま置けます |
| `価格改定のご案内.dc.html` | 制作時のデザイン原本（デザインツール専用ランタイム前提。参照用） |
| `doc-page.js`, `support.js` | 上記原本が使うランタイム。`index.html` には**不要** |

`index.html` はビルド不要・npm不要です。ブラウザで開けば動作します。
`価格改定のご案内.dc.html` は**デザインリファレンス**であり、本番コードではありません。既存コードベースに組み込む場合は `index.html` のロジックとスタイル値を移植してください。

## デプロイ

静的ファイル1枚なので、どのホスティングでも同じです。

```bash
# ローカル確認
cd design_handoff_price_revision_letter
python3 -m http.server 8000     # → http://localhost:8000

# 例: Netlify
npx netlify deploy --prod --dir .

# 例: Vercel
npx vercel --prod

# 例: GitHub Pages
# index.html をリポジトリ直下（または docs/）に置き、Pages を有効化
```

社内配布のみなら、`index.html` をファイル共有に置いてブラウザで開くだけでも動きます（`file://` でも動作しますが、Google Fonts と PDF ライブラリのため**オンライン推奨**）。

### 外部依存（CDN 2件）
- Google Fonts（書体16種）
- `html2pdf.js@0.10.1`（PDFダウンロード）

社内ネットワークが外部CDNを許可しない場合は、この2つをローカルに配置して `<link>` / `<script src>` を差し替えてください。CDNが落ちた場合、PDFボタンは自動的に印刷ダイアログにフォールバックします。

## フィデリティ

**High-fidelity。** 色・タイポグラフィ・余白は確定値です。A4（210×297mm）1ページに収まるよう最大構成（6商品＋最長住所＋担当者行）で調整済み。数値を変更すると1ページに収まらなくなる可能性があります。

## 挙動

- **営業所セレクト** → 所長名・郵便番号・住所・TEL・FAX を一括差し替え
- **書体セレクト** → `#sheet` の `font-family` のみ差し替え（レイアウトは不変）
- **ご発注期日** → カレンダーで設定（初期値 2026-09-06）。あくまで目安で、カード補足と※注記で納品を確約しない旨を明示
- **「吉日」トグル** → 文書の日付を `2026年8月吉日` 形式と `2026年8月19日` 形式で切替（改定実施日は常に日付表記）
- **対象商品** → 1〜6件。6件で追加ボタンが消え、1件で削除ボタンが消える。件数に応じてタイルのカラム数が `min(件数, 3)` に変化
- **案内文編集** → `**太字**` と `__赤下線付き太字__`（`border-bottom: 1px solid #b02418`）、改行が反映。※注記は1行＝1項目
- **リセット** → 「この営業所の編集をリセット」は選択中営業所の上書きのみ削除。「案内文を初期値に戻す」は文書テキスト全項目を初期値に戻す
- **PDF** → `html2pdf.js` で A4 縦・余白0・scale 3 で出力。ファイル名 `価格改定のご案内_<営業所名>.pdf`。生成中はボタンが「PDF作成中…」
- **印刷** → `window.print()`。`@page { size: A4; margin: 0 }` と `@media print` で操作バーを非表示、影を除去

## 状態管理

`localStorage` キー `taiyo-price-letter-v1` に1オブジェクトで永続化。

```js
{
  i: 0,                            // 選択中の営業所インデックス
  offices: {                       // 営業所ごとの上書き（未設定項目はマスターの値）
    "小倉営業所": { chief, zip, tel, fax, address, contact, mobile }
  },
  doc: {                           // 文書共通
    issueISO: "2026-08-19",        // 文書の日付
    effectiveISO: "2026-10-01",    // 改定実施日
    deadlineISO: "2026-09-06",     // ご発注期日（目安）
    kichi: false,                  // 吉日表記フラグ
    font: "noto-sans",
    products: ["トイレットペーパー", ...],
    /* BODY_FIELDS の各 key（recipient, title, lead, ... closing） */
  }
}
```

読み出しは 上書き値 → マスター/初期値 のフォールバック（`val()` / `doc()` / `body()`）。
サーバー通信・データ取得は一切ありません。営業所マスターは `index.html` 内の `OFFICES` 配列（19件、氏名・住所・電話・FAX）。介護保険事業所番号は文書からは削除済みのため配列にも含めていません。

## 既存コードベースへ移植する場合

- 移植対象は `index.html` の3点: `OFFICES` / `FONTS` / `BODY_FIELDS` のデータ定義、`rich()` と `jpDate()` の整形ロジック、`#sheet` のマークアップとスタイル値
- A4レイアウトは印刷前提のため、レスポンシブ化せず固定幅（`210mm`）のまま実装してください
- 営業所マスターを社内システムから取得する構成にする場合、`OFFICES` を API 応答に差し替えるだけで他は変更不要です
